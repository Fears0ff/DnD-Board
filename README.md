# DnD Board

Общее игровое пространство для D&D в доверенной локальной сети или VPN. Одна установка — одно игровое пространство. Приложение не автоматизирует броски, атаки, урон, HP или инициативу: числовые значения вводятся и изменяются вручную.

## Возможности

### Игра и поля

- собственная регистрация и вход по логину и паролю, включая Unicode/кириллические логины без учёта регистра;
- первый зарегистрированный пользователь становится мастером, остальные — игроками; управление ролями защищает последнего мастера;
- несколько полей: мастер отдельно выбирает просматриваемое поле и активное поле, которое видят игроки;
- мастер может создавать и редактировать токены, менять HP и инициативу на любом, в том числе неактивном поле;
- игрок перемещает только собственные токены на активном поле, мастер — любые токены;
- HP изменяется вручную, в том числе кнопками ±1; мастер видит HP всех токенов, игрок — только своих;
- сетка, масштабирование, панорамирование и перетаскивание с привязкой к клеткам;
- ручная инициатива каждого поля в отдельной левой панели с изменяемой шириной;
- синхронизация через WebSocket и polling каждые 4 секунды при его недоступности.

### Изображения

- PNG, JPEG и WebP до 15 МиБ и 8192×8192 пикселей;
- проверка сигнатуры и структуры файла на сервере, а не только MIME-типа;
- фон поля, изображения токенов и карточек компедиума;
- авторизованная раздача по `/api/board-image?key=…`; в БД сохраняются ключи, а не временные URL;
- удаление заменённых изображений и очистка объектов без ссылок старше 24 часов.

### Компедиум, листы и заметки

- восемь типов карточек: `spell`, `item`, `monster`, `character`, `species`, `class`, `feat`, `background`;
- поиск и фильтры, просмотр, создание, редактирование, удаление и копирование карточек;
- видимость `private/shared`; права проверяются сервером;
- атомарный JSON-импорт до 500 карточек и 20 МиБ с ошибками, привязанными к элементам;
- схемы импорта JSON Schema draft 2020-12 находятся в `docs/import-schemas/v1/` и генерируются из контрактов командой `npm run gen:compendium-schemas`;
- лист персонажа с семью вкладками, производными модификаторами и бонусом мастерства;
- создание листа из карточки `character` делает независимый снимок — дальнейшей автоматической синхронизации нет;
- автосохранение листов и заметок с задержкой 1,5 секунды, одним активным запросом, очередью изменений и `expectedVersion`; конфликт версий возвращает HTTP 409 и требует явного выбора пользователя;
- личные Markdown-заметки строго приватны для владельца, включая мастера; preview очищается от опасного HTML.

### Desktop и резервные копии

- Electron-оболочка с локальной SQLite БД, uploads, постоянным секретом сессий, tray, single instance и health gate `/api/health`;
- перед применением новых миграций создаётся согласованный снимок через `VACUUM INTO`;
- сохраняются пять последних pre-migration backup-файлов;
- Windows x64 собирается только нативно в GitHub Actions на `windows-latest`; Linux/Wine cross-build не используется.

## Требования

- Node.js 22 для текущей разработки и desktop-сборки;
- npm;
- для E2E — Chromium. Используется системный `/usr/bin/chromium`, если доступен, иначе установите браузер командой `npx playwright install chromium`.

## Запуск для разработки

```bash
npm ci
cp .env.example .env
```

Задайте в `.env` длинный случайный `APP_SECRET`. Локальная конфигурация:

```dotenv
APP_ID=dnd-board
APP_SECRET=replace-with-a-long-random-secret
SQLITE_PATH=./data/app.db
LOCAL_STORAGE_DIR=./data/uploads
MEDIA_STORAGE_BACKEND=local
DND_BACKUP_DIR=./data/backups
DATABASE_URL=sqlite://local
```

`DATABASE_URL` оставлен для совместимости с платформенным шаблоном; фактический путь SQLite определяется `SQLITE_PATH`. Не публикуйте `.env`, секреты, БД и uploads.

```bash
npm run dev
```

Приложение доступно на `http://localhost:3000`. Миграции применяются автоматически. Runtime-данные находятся в `data/` и не коммитятся.

## Хранение изображений

Реализация выбирается один раз при старте:

- `MEDIA_STORAGE_BACKEND=local` — файлы в `LOCAL_STORAGE_DIR`;
- `MEDIA_STORAGE_BACKEND=platform` — platform object storage;
- без явного значения platform выбирается только при наличии полного набора platform-переменных, иначе используется local.

Старые объекты читаются через backend, записанный в `mediaAssets`, поэтому смена backend для новых загрузок не ломает старые ссылки. Платформенный SDK находится только на сервере; учётные данные не попадают в браузер.

Для platform preview/published runtime хранение, сервер и API-вызовы расходуют квоту владельца. Сайт будет тарифицироваться по фактически используемым облачным сервисам и API-вызовам; реальные списания доступны в настройках владельца. E2E всегда принудительно использует изолированное local-хранилище.

## Production-сборка

```bash
npm run check
npm run build
npm start
```

Сборка создаёт:

- `dist/public/` — клиент;
- `dist/boot.js` — bundled HTTP/tRPC/WebSocket-сервер;
- `dist/node_modules/` — минимальный platform-specific runtime нативного SQLite-драйвера.

Нативный бинарник не переносится между ОС: production-сборку нужно выполнять на целевой платформе.

## Windows desktop

На нативной Windows-машине с Node.js 22:

```bash
npm ci
npm run dist:win
npm run smoke:desktop
```

GitHub workflow `.github/workflows/windows.yml` последовательно выполняет `npm ci`, typecheck, integration tests, desktop build с пересборкой `better-sqlite3` под ABI Electron, нативный smoke test и NSIS packaging. Готовый `DnD-Board-Setup-*.exe` публикуется как artifact `dnd-board-windows-x64`.

Desktop хранит БД, uploads, backups, секрет и логи в изолированном каталоге `userData`. При обновлении сначала сделайте отдельную копию этого каталога. Автообновление не реализовано. Самосборный установщик не имеет коммерческой цифровой подписи, поэтому Windows SmartScreen может показать предупреждение; запускайте только artifact из доверенного GitHub-репозитория после проверки его происхождения.

## Проверки

```bash
npm run check             # TypeScript клиента, сервера, контрактов и desktop
npm run test:integration # миграции, backup, auth, игра, media, компедиум, листы, заметки, WS
npm run test:e2e         # production build + изолированные браузерные сеансы
```

E2E-runner поднимает отдельный сервер на свободном порту 3100–3199, использует временные SQLite/uploads-каталоги и удаляет их после завершения. Пользовательская БД, рабочие uploads и порт preview 3000 не затрагиваются.

Базовый GitHub Actions CI запускает typecheck, integration tests и production build. Отдельный native Windows workflow проверяет desktop и формирует установщик.

## Архитектура

- **React + TanStack Query + tRPC** — UI и типизированный HTTP API.
- **Hono** — HTTP-сервер и health endpoint `/api/health`.
- **SQLite + Drizzle** — данные и транзакции; `PRAGMA foreign_keys=ON`, WAL и `busy_timeout`.
- **`schema_migrations`** — единственный учёт применённых миграций. Параллельный ручной DDL не используется.
- **Вертикальные срезы** — `contract → router → service → repository → UI`; игровые операции, media, компедиум, листы и заметки разделены.
- **WebSocket `/ws`** — только уведомления `{type, revision}`. Полное состояние и все мутации проходят через HTTP API. Личные листы и заметки не попадают в общий realtime-трафик.
- После commit публикуется новая ревизия; клиент повторно запрашивает состояние после открытия WS, чтобы закрыть гонку HTTP-снимка и подписки.
- Пароли хешируются через scrypt с солью. Сессия — подписанная httpOnly SameSite=Lax cookie; роль читается из БД на каждый HTTP-запрос.
- Права и видимость HP проверяются на сервере, а не только скрытием кнопок.

## Границы эксплуатации

Сетевая модель предназначена только для доверенной LAN/VPN. Не выставляйте самостоятельную установку напрямую в публичный интернет: HTTPS-терминация, внешняя политика доступа и hardened public deployment в задачи приложения не входят. Preview платформы является средством просмотра и проверки, а не рекомендацией по публичному развёртыванию.
