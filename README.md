# DnD Board

Общее игровое поле для D&D в доверенной локальной сети или VPN. Приложение рассчитано на мастера и игроков без автоматических бросков, атак, урона и инициативы.

## Что уже работает

- собственная регистрация и вход по логину и паролю, включая Unicode/кириллические логины без учёта регистра;
- первый зарегистрированный пользователь становится мастером, остальные — игроками;
- управление ролями с защитой последнего мастера;
- несколько полей: мастер может отдельно просматривать любое поле и отдельно выбирать активное поле, которое видят игроки;
- мастер может редактировать токены, HP и инициативу на любом поле; активность влияет только на то, какое поле видят игроки;
- создание, редактирование, удаление и ручная очистка токенов;
- владельцы токенов: игрок может перемещать только свои токены, мастер — любые;
- изменение HP мастером кнопками ±1 с ограничением диапазоном от 0 до maxHP;
- HP видны мастеру на всех токенах, а игроку — только на его собственных токенах; чужие значения скрываются сервером;
- сетка, масштабирование, панорамирование и перетаскивание с привязкой к клеткам;
- ручная инициатива каждого поля в отдельной левой панели, ширина которой изменяется мышью или клавишами со стрелками;
- синхронизация клиентов через WebSocket и polling каждые 4 секунды при его недоступности;
- SQLite, версионированные транзакционные миграции и монотонные ревизии состояния.

Компедиум, листы персонажей, заметки, загрузка изображений и desktop-оболочка пока не реализованы. Для этих сущностей уже заложена часть схемы БД, но пользовательского API и интерфейса нет.

## Требования

- Node.js 22 (также поддерживается Node.js 20, соответствующий `better-sqlite3`);
- npm;
- для e2e — Chromium. Используется системный `/usr/bin/chromium`, если он доступен, иначе установите браузер командой `npx playwright install chromium`.

## Запуск для разработки

```bash
npm ci
cp .env.example .env
```

Задайте в `.env` длинный случайный `APP_SECRET`. Значения по умолчанию:

```dotenv
APP_ID=dnd-board
APP_SECRET=replace-with-a-long-random-secret
SQLITE_PATH=./data/app.db
LOCAL_STORAGE_DIR=./data/uploads
DATABASE_URL=sqlite://local
```

`DATABASE_URL` оставлен для совместимости с платформенным шаблоном; фактическое хранилище определяется `SQLITE_PATH`.

```bash
npm run dev
```

Сервер доступен на `http://localhost:3000`. Миграции применяются автоматически при первом обращении к БД. Runtime-данные находятся в `data/` и не коммитятся.

## Production-сборка

```bash
npm run check
npm run build
npm start
```

Сборка создаёт:

- `dist/public/` — клиент;
- `dist/boot.js` — bundled HTTP/tRPC/WebSocket-сервер;
- `dist/node_modules/` — минимальный platform-specific runtime нативного SQLite-драйвера.

Поэтому каталог `dist/` можно запускать без исходного `node_modules`. Нативный бинарник не переносится между ОС: production-сборку нужно выполнять на целевой платформе.

## Проверки

```bash
npm run check             # TypeScript
npm run test:integration # миграции, auth, права, игровые операции, WS
npm run test:e2e         # production build + изолированные браузерные сеансы
```

E2E-runner поднимает отдельный сервер на свободном порту 3100–3199, использует временные SQLite/ uploads-каталоги и удаляет их после завершения. Пользовательская БД и порт preview 3000 не затрагиваются.

Базовый GitHub Actions CI запускает typecheck, integration tests и production build.

## Архитектура среза

- **React + TanStack Query + tRPC** — UI и типизированный HTTP API.
- **Hono** — HTTP-сервер и health endpoint `/api/health`.
- **SQLite + Drizzle** — данные и транзакции; `PRAGMA foreign_keys=ON`, WAL и `busy_timeout`.
- **`schema_migrations`** — единственный учёт применённых миграций. Параллельный ручной DDL не используется.
- **WebSocket `/ws`** — только уведомления `{type, revision}`. Полное состояние и все мутации проходят через HTTP API.
- После открытия WS клиент повторно запрашивает состояние, чтобы закрыть гонку между HTTP-снимком и подпиской.
- Пароли хешируются через scrypt с солью. Сессия — подписанная httpOnly SameSite=Lax cookie; роль читается из БД на каждый запрос.
- Права проверяются на сервере, а не только скрытием кнопок.

## Границы эксплуатации

Текущая сетевая модель предназначена только для доверенной LAN/VPN. Не выставляйте этот срез напрямую в публичный интернет: HTTPS-терминация, внешняя политика доступа и hardened deployment в задачу среза не входят.
